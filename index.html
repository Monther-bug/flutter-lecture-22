fromJson: one map → one object

lib/models/product.dartinside class Product
factory Product.fromJson(Map<String, dynamic> json) {
  return Product(
    id: json['id'] as int,
    title: json['title'] as String,
    description: json['description'] as String,
    price: (json['price'] as num).toDouble(),
    rating: (json['rating'] as num).toDouble(),
    thumbnail: json['thumbnail'] as String,
    brand: json['brand'] as String?,
  );
}

// The pattern for a whole JSON list → List<Product>:
(json as List).map((item) => Product.fromJson(item)).toList()
factoryA constructor that runs code first, then returns an object.
numJSON writes 10 or 9.99; Dart reads int or double. as num accepts both, .toDouble() makes it a double.
.map(...)Turns every map into a Product; .toList() makes it a List.
Recipe 11 at DummyJSON has "rating": 5. as double crashes there; as num works.
Mobile App Development · Lecture 22

Real example: recipe 11 at DummyJSON ("Chicken Biryani") has "rating": 5, a whole number. json['rating'] as double crashes there with "type 'int' is not a subtype of type 'double' in type cast"; (json['rating'] as num).toDouble() works for all of them.

Service

A service class: ProductApi

lib/services/product_api.dartfirst version
class ProductApi {
  static const String _url = 'https://dummyjson.com/products';

  static Future<List<Product>> fetchProducts() async {
    final response = await http.get(Uri.parse(_url));

    if (response.statusCode != 200) {
      throw ApiException('Server error (${response.statusCode}). Try later.');
    }

    final data = jsonDecode(response.body) as Map<String, dynamic>;
    final productsJson = data['products'] as List;
    return productsJson.map((item) => Product.fromJson(item)).toList();
  }
}

A map, with the list inside "products".

static: call it without creating an object: ProductApi.fetchProducts().

Version 1 with FutureBuilder: start and retry

lib/pages/products_page.dart
class _ProductsPageState extends State<ProductsPage> {
  late Future<List<Product>> _productsFuture;

  @override
  void initState() {
    super.initState();
    _productsFuture = ProductApi.fetchProducts();
  }

  void _retry() {
    setState(() {
      _productsFuture = ProductApi.fetchProducts(); // start a new request
    });
  }

No final this time: retry replaces the Future with a new one.

Version 2 · Provider

Version 2 with Provider: ProductsProvider

lib/providers/products_provider.dart
Future<void> loadProducts() async {
  _isLoading = true;
  _error = null;
  notifyListeners(); // show the spinner

  try {
    _products = await ProductApi.fetchProducts();
  } catch (e) {
    _error = e.toString(); // our friendly ApiException message
  }

  _isLoading = false;
  notifyListeners(); // show the list, or the error
}

Three private fields + getters: products, isLoading, error.

1notifyListeners()Change the fields, then call it: the page rebuilds.
2try / catchIf the code in try throws, run catch instead of crashing.
lib/main.dartChangeNotifierProvider
create: (context) => ProductsProvider()..loadProducts(),
The .. means "create it, call loadProducts(), and give back the provider".
Mobile App Development · Lecture 22

This is the ChangeNotifier from Lectures 13, 14 and 21: change the fields, then notifyListeners(). Provider runs create the first time a widget asks for the provider (here: when the products page opens), so that is when loading starts.

FutureBuilder is fine for one screen; a Provider is better when several screens need the same data, or the data should stay loaded when you leave the page.

Friendly errors

When the internet fails

lib/services/product_api.dartfetchProducts() · final version
try {
  final response = await http
      .get(Uri.parse(_url))
      .timeout(const Duration(seconds: 10));
  // ... check statusCode, decode, map to products (as before)
} on TimeoutException {
  throw ApiException('The server is too slow. Please try again.');
} on SocketException {
  throw ApiException('No internet connection. Check your Wi-Fi or data.');
} on http.ClientException {
  throw ApiException('Could not reach the server. Please try again.');
}
1.timeout(...)Give up after 10 seconds (TimeoutException, from dart:async).
2SocketExceptionFrom dart:io: no network. With http 1.6 it arrives as a ClientException that is also a SocketException, so this line must come first.
on Type: catch only that kind of error.

Live: turn on airplane mode and tap Try again → "No internet connection…". Then set the timeout to 2 seconds and the URL to https://dummyjson.com/products?delay=4000 → "The server is too slow…". On the web there is no SocketException; the ClientException line catches it.

Sending data

Sending data: a POST request

lib/services/post_api.dartPostApi
static Future<Map<String, dynamic>> createPost(String title) async {
  final response = await http.post(
    Uri.parse(_url), // https://jsonplaceholder.typicode.com/posts
    headers: {'Content-Type': 'application/json'},
    body: jsonEncode({
      'title': title,
      'body': 'Sent from my Flutter app',
      'userId': 1,
    }),
  );
  if (response.statusCode != 201) {
    throw ApiException('Could not send the post (${response.statusCode}).');
  }
  return jsonDecode(response.body) as Map<String, dynamic>;
}
headersTell the server "my body is JSON".
jsonEncodeDart map → JSON text (the opposite of jsonDecode).
The answer201 Created
{
  "title": "My first post",
  "body": "Sent from my Flutter app",
  "userId": 1,
  "id": 101
}
Success for a POST is 201 Created; the answer is the new post with "id": 101.
JSONPlaceholder is fake: it answers 201 but saves nothing (GET /posts/101 → 404).
